# T1.9 — partial frozen typography context and lazy scope inspection

## Scope

T1.9 retains size, weight and typed line-height alongside T1.8's family, style
and spacing. It does **not** resolve fonts, grant grouping authority, shape text,
rasterize glyphs, or unlock the original Flexbox page. Public headers/ABI,
Actions and dependencies are unchanged. Base tree is published main `4649e947`
(the same tree as reviewed local candidate `a320b96`).

## Evidence, not a second cascade

The existing source compiler retains accepted source before typed normalization.
The existing winner selection and deferred substitution select the source. For
new fields, successful application supplies the computed output; a failed apply,
failed substitution, discarded declaration, uncertain scope or unsupported
initial keeps the evidence unknown. Sources longer than 64 KiB are not known.
`accepted_source` preserves the declaration, `resolved_source` the substituted
value; both survive inheritance. There is no second selector/cascade or numeric
parser. Known values describe the existing runtime profile, not complete CSS.

Size stores computed CSS px and dependencies. Existing unit-resolution flags
are retained, with parent-relative size keywords also marked parent-dependent.
Weight remains the runtime's narrow integer profile (100–900 and its accepted
names); fractional weights and bolder/lighter are not claimed. Line-height
stores `normal`, `number`, or `absolute_css_px`, its computed value, used px and
dependencies. Normal uses the runtime's **approximate 1.2 multiplier**, not real
font metrics. A parent's 1.5 at 16px and 24px both use 24px, but a 20px child
inherits 30px from the number and 24px from the absolute value. Tests retain this
distinction. Inherited values are evaluated using the child's final size.

Six fields share provenance and transactional ownership. Changed source can
invalidate evidence even if legacy scalar values are unchanged. Old snapshots
stay usable after mutation and allocation failure; they are never a claim of
current document inputs. Coverage remains explicitly incomplete.

## Private comparison contract

`TypographyContext::bind` owns a map version and the exact frozen node record.
Validation checks contextual/runtime origin, backing-to-record association,
exact revision, document lifetime/identity, generation, input/structure/style
and sheet epochs, and evidence profile version. No loose scalar/evidence map
is accepted. Two contexts from different revisions are `unproven` even if
numbers match. Clones of the same immutable revision may compare.

Comparison precedence is identity failure → `unproven`; otherwise any known
tracked difference → `different`; otherwise any unknown/unsupported field →
`unproven`; otherwise `equal_for_tracked_fields`. Equal unknowns are not proof.
This result carries no SyntheticFaceSeal, font-face capability or renderer
permission. T1.7 integration tests show that equal real-cascade contexts cannot
install synthetic authority and that legitimate old synthetic authority cannot
be reused after a size mutation/new revision. Untracked source/font features,
script/language, direction, writing mode and grouping barriers remain outside
this partial comparison.

## Scope optimization and measurement

Only a winning deferred typography field requests inspection of the frozen
custom-property scope. Each node computation memoizes the result for all six
fields and exits at the first invalid/unproved terminal, including ancestors.
No global cache and no narrowing to referenced variables: the deliberate T1.8
conservatism is preserved even for a successful fallback affected by unrelated
invalid entries. Private opt-in thread-local counters never alter decisions.

See `validation/t19/scope-benchmark.md` and `scope-summary.csv` for measured
baseline/candidate evidence, identical output/diagnostic checks, wall/CPU
medians and dispersion, and process high-water RSS. The baseline replaces only
the lazy scan with the old eager scan **inside T1.9**; it does not claim the total
cost of all T1.8 versus all T1.9. No-change prepare/commit still recomputes nodes
in this runtime and is reported separately, not misrepresented as a cache hit.
