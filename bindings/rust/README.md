# AetherUI Rust binding

**Status: not implemented.** This directory defines the integration contract a Rust crate must
satisfy — it is the spec a contributor implements against, not working code yet. The binding
consumes the *installed* C ABI only; it must never link against C++ symbols, a private native
header, or a CMake build tree. [`bindings/dotnet/`](../dotnet/) is the reference implementation of
the same contract in a different language — when a lifetime or ownership question isn't obvious
from this document, that binding's `SafeHandle`-derived classes (`NativeDomDocument`,
`NativeLayoutResult` in `AetherUI.Core.Native.Interop`) are the concrete precedent to mirror.

Rust is arguably the most natural non-C++ language for this ABI. The ABI is already shaped like
idiomatic Rust FFI before a single line of binding code exists: opaque handles map directly onto
`#[repr(C)] struct Foo { _private: [u8; 0] }`-style opaque pointer types, integer status codes map
directly onto `Result<T, AetherError>` with no exception-unwinding machinery to bridge, and the
`aether_*_destroy`/`aether_*_free` pairing maps directly onto `Drop`. Nothing about the ABI needs
translation through a garbage-collected runtime, a VM, or a managed marshaling layer the way it
does for the JVM or the CLR — the ownership and error-handling *shape* of the C ABI and the
ownership and error-handling shape of safe Rust are close to isomorphic.

## Intended scope

The binding will expose DOM parsing, the style runtime, layout, hit testing, and display-list
generation as an idiomatic, safe Rust API. It may be used headlessly (parse → resolve → layout →
read the display list, no pixels drawn) or combined with a renderer supplied by the application or
a future platform crate. Windowing, text shaping, and rasterization are not implied by the core
binding — that split mirrors how `AetherUI.Windows` sits on top of the .NET binding without being
part of it.

### Sketch of the target shape

Not an API commitment — illustrative, to make the ownership contract concrete before anyone writes
FFI code:

```rust
pub struct Document { /* wraps aether_doc_t */ }

impl Document {
    pub fn parse(html: &str) -> Result<Self, AetherError> { /* aether_doc_create + ...parse_html */ }
}

impl Drop for Document {
    fn drop(&mut self) { /* aether_doc_destroy */ }
}

pub struct StyleRuntime { /* wraps aether_style_runtime_t */ }

impl StyleRuntime {
    pub fn new(options: Options, env: Environment) -> Result<Self, AetherError> { .. }
    pub fn add_stylesheet(&mut self, css: &str, layer: Layer, source_name: &str) -> Result<StylesheetHandle, AetherError> { .. }
}

pub struct LayoutEngine { /* wraps aether_layout_engine_t, holds the boxed measurer closure */ }

impl LayoutEngine {
    pub fn new(measure: impl Fn(&str, &ComputedStyleView, f32) -> TextMetrics + 'static) -> Result<Self, AetherError> { .. }
    pub fn layout(&self, doc: &Document, styles: &StyleRuntime, width: f32, height: f32) -> Result<LayoutResult<'_>, AetherError> { .. }
}

pub struct LayoutResult<'a> { /* wraps aether_layout_result_t, borrows the engine lifetime */ }

impl<'a> LayoutResult<'a> {
    pub fn hit_test(&self, x: f32, y: f32) -> Option<Node<'_>> { .. }
}

impl Drop for LayoutResult<'_> {
    fn drop(&mut self) { /* aether_layout_result_destroy */ }
}
```

Every owning wrapper implements `Drop`, so cleanup is deterministic and scope-based with no
explicit `close()` call required — the same guarantee `SafeHandle` gives on the .NET side, but
enforced by the compiler instead of runtime discipline. Borrowed types (`Node<'a>`, a layout box
view) carry a lifetime parameter tied to their owning `Document`/`LayoutResult`, so the borrow
checker rejects a node reference that outlives its document at compile time wherever the lifetime
can be expressed — the FFI boundary itself cannot enforce this, so the safe wrapper is the only
place this guarantee can actually live.

## `unsafe`/`sys` boundary

All `unsafe` code is isolated to a thin `sys`/`ffi` module — either hand-written `extern "C"`
blocks matching `aether.h` exactly, or generated by [`bindgen`](https://rust-lang.github.io/rust-bindgen/)
run against the installed header as a build-time step. Everything outside that module is safe Rust:
no `unsafe` in the public wrapper types, no raw pointer arithmetic, no manual lifetime transmutes
outside the handful of functions whose job is specifically to convert a raw `aether_node_t` into a
lifetime-bound `Node<'a>`. A `build.rs` drives native-library discovery and, if `bindgen` is used,
regenerates `sys` bindings from the installed header rather than a vendored copy checked into the
crate.

## Native library discovery

Development uses the installed CMake/pkg-config contract documented in `native/README.md`:

```text
<install-prefix>/include/aether/aether.h
<install-prefix>/lib/pkgconfig/aetherui-core.pc
<install-prefix>/bin/aether_core.dll                Windows
<install-prefix>/lib/libaether_core.so               Linux
<install-prefix>/lib/libaether_core.dylib             macOS
```

`build.rs` should prefer the [`pkg-config`](https://crates.io/crates/pkg-config) crate against
`aetherui-core` where `pkg-config` is available (respecting `PKG_CONFIG_PATH`), with a documented
environment-variable override (e.g. `AETHERUI_INSTALL_PREFIX`) for environments without it. It must
never fall back to scanning `native/build/` or a developer's private CMake cache — see
[`examples/cpp/abi-info`](../../examples/cpp/abi-info/) for the equivalent discovery pattern the
crate's `build.rs` should mirror rather than reinvent.

## ABI verification

Before creating a single handle, the crate must call and validate, ideally once at process startup
via a `OnceLock`/`std::sync::Once`-guarded init path:

```text
aether_abi_version()
aether_abi_capabilities()
aether_paint_command_size()
```

Accept only a compatible ABI version (same major, minor at least what the crate was written
against), require only the capability bits the crate's own calls depend on, ignore unknown
capability bits from a newer library, and size every display-list command buffer from
`aether_paint_command_size()` at runtime — never `std::mem::size_of::<sys::aether_paint_command_t>()`,
since a `bindgen`-generated struct layout can silently drift from the library actually loaded at
runtime if the two weren't built from the same header revision.

## Ownership model

Every owning native handle is wrapped in a Rust struct whose `Drop` impl calls the matching
`aether_*_destroy`/`aether_*_free`. There is no finalizer fallback to reason about — Rust has none,
which is exactly the point: the same static guarantee that makes `Drop` reliable also means a
double-free or use-after-free bug in the wrapper is a bug in the wrapper's `unsafe` code, not a
runtime GC-timing hazard callers have to guard against themselves.

Nodes and layout boxes are borrowed views. The safe API represents them as `Node<'a>`/`LayoutBox<'a>`
carrying the lifetime of their owning `Document` or `LayoutResult`, so a caller cannot hold one past
its owner's `drop()` in code the borrow checker can see through. A document reparse invalidates
every node for the old tree at the native level even though the Rust borrow is still technically
alive from the compiler's point of view (reparsing goes through `&mut Document`, not a fresh
lifetime) — the wrapper must track a generation counter and have every node accessor return
`Result<_, AetherError::Disposed>` once the generation no longer matches, rather than trust the
lifetime system to catch a case it structurally cannot. Display-list text and gradient-stop data
are copied into owned `String`/`Vec<f32>` values before the command — and the list that owns it —
is freed.

## Callback safety

Native callbacks (text measurement, scroll-offset queries) are synchronous and run on whatever
native thread is currently inside the call that triggered them. Rust closures passed as callback
user-data must be boxed and given a stable address (`Box::into_raw`) rather than passed as a stack
pointer, and the boxed closure's lifetime must be tied to the owning `LayoutEngine`/builder so it is
only freed after native code can no longer invoke it. Every callback trampoline must wrap the
closure invocation in `std::panic::catch_unwind` and return a documented safe fallback value on
`Err` — a Rust panic unwinding across an `extern "C"` boundary back into C++ is undefined behavior,
not a panic the C++ side can catch, exactly like the ABI's own rule about exceptions never crossing
the boundary.

ABI 0.1 requires serialized access to a handle graph — no two threads may operate on the same
document, style runtime, layout result, or display list concurrently. Owning wrapper types should
be `!Sync` by default (or wrap their handle in a `Mutex` if cross-thread use is a deliberate design
goal) so that sharing a `Document` across threads is a compile error or an explicit, documented
locking decision — never a silent data race the native side has no way to detect.

## Release gates

Before publishing a crate version: verify ABI negotiation against the pinned native version, run
`cargo test` under Miri or a leak sanitizer for `Drop`-based cleanup ordering, fuzz a measurement
callback that panics and assert `catch_unwind` contains it with the native call still returning
cleanly, verify display-list command decoding against a fixture with every paint-command variant,
and confirm `cargo doc` builds cleanly with every public unsafe invariant documented on the `sys`
module's items (`bindgen`'s `--generate-cstr` and doc-comment passthrough should be enabled so the
generated bindings carry the original header comments).
