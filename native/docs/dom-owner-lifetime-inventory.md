# DOMsync ownership and live-reader inventory

Current source basis: **e2c06e7458557946c76860e8ee140ec9fb615698**, read from `frozen-e2c06e7/`. This consolidates the old 54dd45d work notes, whose archival copy is `OWNER-LIFETIME-INVENTORY-history-54dd45d.md`. Old statements about missing loaded-document ownership or retaining a complete retired style payload are superseded here. This inventory is an audit input, not an independent safety PASS.

## Semantics and admitted boundaries

- Native reads/mutations of live DOM, owner metadata, epochs, claim metadata and mutable relay fields remain owner-thread operations. A physical storage pin is not permission for concurrent reads/mutation or permission to access an explicitly retired node as live.
- A raw legacy document/node is borrowed. Destroyed raw handles, duplicate destroy and raw use after lifetime ends are outside the contract. No API can resurrect an already freed raw pointer by inspecting it. Derivative handles must themselves remain retained for the complete call.
- `aether_dom_owner_release_v1` is refcount-only ownership release, not logical retirement. GC of an implicit owner can leave its document live while a derivative retains it. Explicit owner-thread Dispose/abort uses `aether_dom_owner_retire_v1`, marking logical death immediately, then releases ownership.
- No guaranteed owner-thread dispatch queue is used. No finalizer calls owner-thread legacy `doc_destroy` as a substitute for release. LayoutResult's raw `size_t references` is still owner-thread, non-atomic; there is no new finalizable layout API in this work.
- Pure token/Version/NeedsRender queries do not deliver callbacks or import. Allocation counters are diagnostics, not authority. A changed status/epoch prevents certification even where old physical storage remains valid.

## Ownership graph and destruction

`dom/dom_types.h`: root EditableNodeStorage owns `aether_doc_s`; its `editable_nodes` registry owns each editable node's storage. Node `editable_storage`, identity `storage`, document owner links and owner-control document links are weak. `LegacyDocumentLease` is external and owns root storage; root has only a non-owning bookkeeping pointer to that cell. Internal shared documents never fabricate a legacy external cell.

`DomNodeOwnerPin::current_root` strongly retains the current root. Identity has only a weak relay. Independent derivatives own the relay strongly. Consequently the graph is derivative → relay → root → registry → node → weak relay, not a strong cycle. Historical provenance root pins are separate from current-owner relays. Generated nodes are pinned by shared generated storage; origin/ancestor editable storage and origin/ancestor relays are captured independently where a historical generated payload needs them.

`document_node.cpp::aether_doc_create` reserves root/node/control/cell before publishing raw output. `aether_doc_destroy` holds a local root pin, marks owner/root/registry nodes logically dead, retires interaction metadata without allocation, disposes unmanaged children while registry storage still exists, releases registry ownership, nulls the legacy pointer and deletes the external cell. It never touches doc after the last local pin leaves. A retained root header therefore does not itself retain the old entire registry after explicit destroy.

`dom_owner.cpp` allocates its external owner cell first, calls strong legacy create, then transfers the root ownership from the legacy cell without further allocation. `owner_retire` verifies owner thread and is idempotent. `owner_release` deletes only the external cell.

`dom_types.h::~aether_doc_s` is the final physical cleanup path for factory roots still logically alive. It marks dead and clears registry/unmanaged children. Its safety depends on every legitimate live reader retaining root or relay, so no such reader can coexist with the last physical release. Explicitly retired roots skip repeated traversal. This is the central invariant under independent review, not a claim that arbitrary token-only reads are thread safe.

## Live-reader families and their protecting owners

1. **Raw DOM API and identity/token queries.** `dom_snapshot.cpp::aether_dom_read_token_v1/read_node_identity_v1` read owner-thread/alive and root epochs. Entry requires a caller-owned raw borrow, node lease, or managed document borrow. Legacy getters in node/element/document files are synchronous borrowed reads; they do not acquire lifetime after entry. `NativeDomDocument` protects managed calls with `Borrow`.
2. **Node leases.** `dom_snapshot.cpp::aether_dom_node_lease_s` owns node storage, identity, original document root and live-owner relay. Its destructor only releases refs. `lease_get` returns the retained pointer; mutable live use still follows thread/retirement rules. A→B→C adoption updates the shared relay, so an old lease protects the new live root as well as its old physical provenance.
3. **Typed snapshots.** Every `DomSnapshotNode` owns node storage, identity and live-owner relay; the snapshot vector includes the root, registry nodes and caller-known leases. Attributes/text/state/value/edges are copied values. Known adopted nodes get their own relays rather than relying on the target document's root. Reads of copied snapshot values require only snapshot ownership. Acquiring one remains owner-thread and revalidates its DOM token.
4. **Prepared DOM edits.** `dom_edit.cpp::Domain` retains each affected root/control and captures DOM token, `style_tree_epoch`, interaction serial and registry. `pins`, `generated_pins` and adoption relays retain every staged raw endpoint/list member. Validate checks all domains before staged links are used. A FULL style R2 can replace generated storage without changing the DOM token, so the independent style-tree epoch is essential. Scalar State does not traverse/pin the whole tree.
5. **Legacy structural/adoption paths.** `node.cpp` preflights source/destination roots, registries, relay objects and generated descendants before publishing ownership. Typed materialization kinds 11/13 preserve existing subtrees as opaque identities, create only provisional new nodes, and publish a new Document plus adoption in one edit. Abort retires only provisional nodes/new owner. Source/destination relay swaps happen while old and new roots remain pinned.
6. **Style payloads.** `css/frozen_node_record.{h,cpp}::FrozenNodePayload` owns node editable storage/generated leaf, original document storage, node live relay, ancestor/style-origin storage vector and ancestor/style-origin relay vector. `freeze_node_payload` pins before validation and translates errors at its no-throw boundary. A pseudo retired before its host is adopted still owns the host relay, so its origin's new owner cannot disappear underneath retained live-token reads.
7. **Retired payloads.** `css/style_revision.h::FrozenRetiredNode` copies only identity/generated/node/document lifetime and owner storage/relay bundles from the source payload. It does **not** retain the full source payload, computed styles, scopes or measures. This preserves the original retired-payload resource-release oracle while keeping provenance/origin memory safe. Bundle copies are prepared before publication.
8. **Maps, revisions, transactions and computed handles.** `css/style_map_version.*::MapVersion` has an explicit document lease even for an empty map with provenance; backing records pin actual nodes/current roots. Wholly unbound empty maps have no DOM to pin. `structure_valid/inputs_current` live epoch reads are protected by those owners. `style_revision.*` revision/header/build inputs and `style_runtime_core.cpp::aether_style_transaction_s` retain document storage plus payload/base/candidate owners. Public computed-style handles retain record and/or revision, not merely identity tokens. Stack adapters are borrowed only within a pinned call.
9. **State journal.** `state_reconciliation.cpp::live_entry` first verifies real payload membership and same identity ownership before reading mutable `alive/attached`. Record subject tokens alone do not confer ownership. The base revision pins eligible nodes. Structural/style-tree epoch checks exclude stale topology before reconciliation. Foreign token controls that alias an old raw key are rejected before mutable liveness reads. The journal does not own root relays, which would create a document cycle.
10. **Legacy transitions.** `animations/transition_runtime.cpp::transition_claim` owns node storage, identity, historical root and live-owner relay. Active, finished and prepared candidate states retain those claims. Validity/staleness/has-active/Tick/override reads are protected by the runtime/candidate state. Input observation/retirement raw pointers are borrowed for the native call. Candidates retain runtime instance/lifetime, compare mutation/status revisions, and publish payload without replacing the public handle. The refactor does not replace legacy behavior with contextual transitions.
11. **Contextual transitions.** `animations/contextual_transitions.cpp::Entry` retains node/document storage and live relay in immutable State and retained batches. It obtains ownership from authentic identity storage/relay, not by dereferencing a possibly sentinel `event.node`. Existing identity-only legacy inputs remain borrowed and gain no new owned-DOM promise. Has-active/sample/owner-extraction reads are protected by retained entry owners.
12. **Geometry/layout/render.** Production `layout_engine.cpp` captures the actual geometry document and a full `EditableDomPin` (including text/comments and live relays), even for null/unbound/empty style maps. Both initial and frozen `LayoutAssets` retain it. Its pure `structure_valid` reads are thus protected independently from map provenance. `operation_pin.h::CallbackEpochGuard` holds root/token across callbacks; style/layout operation pins retain maps/assets/geometry. Raw layout boxes require the layout owner. Engine measure-document tokens live only inside this protected operation and are cleared on unwind. Display-list callback guards use the same retained geometry/style ownership.
13. **Bound CSS source stages.** `aether_dom_style_binding.*` binding/stages retain document storage and the runtime cell while compiling/capturing candidates. DOM-edit domains retain the corresponding source/destination binding stages; all slot mutations and validation precede no-fail publication. Direct legacy mutators participate. This is not a parse/rebind recovery mechanism.
14. **Interaction native metadata.** `dom_interaction.cpp::DomInteractionRegistry` strongly owns document/control/binding and claims. Owner control stores only a weak registry; each claim holds a weak registry, node storage and live-owner relay; node identity stores only weak claims. No root-registry-claim strong cycle is introduced. Prepared stages retain registry/claim and reserved route/loss data. Claim/owner handle release only drops refs. Logical retire/dispose and exact loss acknowledgment are owner-thread. Destroy/reparse retirement freezes the first loss without allocation. Reading a retained loss after logical document destruction is supported under its retained registry, until host/binding replacement revokes it.

## Managed borrowing and publication

- `NativeDomOwner.cs::NativeDomOwnerHandle.ReleaseHandle` only calls owner_release. `NativeDomBorrow` uses DangerousAddRef/DangerousRelease for finalizable owners; it is a scoped struct, not a reusable copied handle. `NativeDomDocument.CreateEmpty` uses this path. Legacy Parse remains explicitly disposed; finalizable implicit Document does not add mandatory public IDisposable to DocumentNode.
- `NativeDomDocument.cs`: all instance native operations, including pure DocumentElement/Body/child/state/tag/attribute calls, use Borrow. Dispose retires on the owner thread then releases the SafeHandle. A returned raw Handle remains borrowed; it does not extend lifetime for external code.
- `StyleRuntimeInterop.cs` now keeps `_loadedDocument` independently from `_ownedDocument` and uses `BorrowLoadedDocument` for resolve/state paths. Load and CreateResolvedStyleMap borrow their explicit document. `StylePublicationInterop.cs` stages retain the loaded owner and borrow it for token/commit/current checks. `StyleRuntimeInterop.DomBinding.cs::PreparedDomBinding` retains both old/new managed owners and borrows them for validation/commit; publication swaps the loaded owner and index. Disposing stages clears their managed owner refs. Runtime Dispose clears `_loadedDocument`; it retires only its own `_ownedDocument`, not externally supplied ownership.
- `NativeDomBinding` wrappers own `NativeDomNodeRecord` leases. Imports stage copied payloads, retained leases, reciprocal links and owner registries before swapping mirrors. Cross-document `_adoptedWrappers` is allocated before native commit, avoiding lazy Dictionary.Values allocation afterward. `PreparedDomIndex` is prepared for structural edits in both domains and published by swap.
- `NativeDomBinding.ImplicitDocument.cs` creates a private finalizable owner/root/binding, prepares kind13 with every old bound wrapper imported first, and exposes new mappings only after native commit. Abort destroys the edit before retiring the new root. Root/wrapper ownership then extends native life; no native strong pointer back to a managed object is introduced.
- Managed interaction SafeHandles only release native handles in finalizers. Host owner-thread Dispose retires authority before releasing. Session pins the old component registry for exact pending target-only blur delivery. New authority and bit stamps are checked before cleanup; old records remain retained through the lifecycle batch. e2 has a bounded one-batch entry guard, but review subsequently found capture OOM was outside its retry-blocking catch; fix852f4bd is a separate later cut under test, not part of the e2 approval claim.
